`Execution::reconcile_evictions(eviction::Pass, retained, working, clock)` pages
only the signed working producer-index root. At most128 records are considered;
object, prospective-byte, deadline and aggregate lookup-read budgets apply.
The current admitted Main snapshot is read under its source-generation guard.
Main's exact tree, not the union containing temporary ingest claims, identifies
its current working demand. Other jobs/branches/retention remain authoritative
through the controller's fresh complete-roster assessment and scoped fences.

Continuation binds policy, exact commit, Main revision and immutable working root.
It uses the index's exact after-key check. Copy and eviction cursors have different
bases. A held object resumes from the last successful key; an initial hold restarts
the page. Suffix completion never proves prefix coverage or global convergence.
`storage_converged` remains unknown.

Producer records may embed optional `control_retention`. Absent serialization
remains unchanged. Its canonical grant must validate and name the exact native
control-document Object for that media Object. This is an existing keeper
metadata-retention grant, not native byte custody. The controller independently
checks actual grant/store state, native retained snapshot membership/bytes,
configured fault domains, observed storage separation and all live protection.
The receiver never manufactures a grant or treats missing declarations as absence.

Actual working ingress and deterministic forward-copy recipes remain distinct.
The keeper recipe may be its original publication or the exact completed reverse
backup. Unknown intent, conflicting recipes, missing grants or missing custody
hold; this phase does not copy missing deprecated bytes or restore working bytes.
Before a fresh eviction, enabled durable handoff can release only the temporary
ingest claim after retained readback. Other protection can still keep the object.

Preview performs readonly native planning. It neither releases claims, saves an
action nor removes bytes. A retained ingest/job obligation can yield `protected`.
Apply uses a deterministic operation key and saves/readbacks/adopts the full
original before invoking the existing controller. The per-object report retains
copy/backup recipes, handoff results, planned ID and saved eviction result/failure.
New eligibility is checked after preview, and admission/deadline precede effects.
Successful receipts survive expiry or ref drift in post-effect checks.

A saved original wins over every later preview. Before invoking fresh removal,
the durable worker inspects that original controller status. Completed work uses
`resume`, reconciling accounting without removing bytes again. Uncertain native
intent returns `uncertain`; it never repeats the effect. Historical completion
can coexist with restored same-hash bytes and grants no removal of that new birth.
Original direct-ingress saved actions are found before keeper index/payload opens.
An offline keeper payload need not prevent completed accounting reconciliation;
the backend's required metadata/control stores must remain available.

The private receiver profile adds `phase`: `copy` (default), `eviction_preview`,
or `eviction_apply`. The last two require signed eviction permission and a matching
pending namespace binding. The phase and locations come from private fixed config,
never the event. Separate copy/eviction passes use the same authenticated commit;
there is no new HTTP authority, daemon or cache initialization. Old profiles keep
copy-only default dispatch, with optional durable handoff as previously defined.

Safe stale-plan replacement, producer-root advancement/retention, absent-working
reacquisition, missing deprecated backup repair, full native HTTP acceptance and

final archival deletion and metadata forgetting are separate contracts.
