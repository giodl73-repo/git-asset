Policy is private, fixed operator configuration. Its bounded canonical identity

domains, required alias and permissions. Advancing these pinned minima or changing

publisher is introduced. Default permissions deny selection and copy.

The copy entry authenticates provenance/policy before selection, refuses old
unfenced namespaces before mutation, reconciles only the verified immutable commit
and holds its actual admitted generation. It projects existing namespace demand
with a bounded metadata reader and requires the exact candidate at the enrolled
destination alias. Native Copier then reopens original source custody and applies
the original destination publication. No source census or payload fallback occurs.
Each call handles exactly one object within existing lifecycle/protection/copy
budgets. A call never asserts whole-project convergence.

Ref/issuer admission is checked again immediately before the native call. Git may
advance during a copy: additions remain retained, and post-effect status reports
stale/expired/unavailable admission while returning the original successful copy
receipt and live guards. It does not turn completed publication into an ordinary
retryable failure. Native uncertain outcomes preserve their existing error and
original plan handle; use Copier status/resume/reopen, never invent a new attempt.

The returned guard pins source generation and actual native source/destination
reads. Drop or process exit releases live handles, never durable claims or bytes.
This copy path does not settle ingest retention, evict, reacquire, cancel, approve
creative selection or claim independent physical failure domains. Those require
their existing explicit proofs/permissions. Frozen policy is not mixed-authority
handoff, custody evidence or an eviction grant. Native copy HTTP intake is now
described in [NATIVE-RECEIVER](NATIVE-RECEIVER.md). Full retention/eviction
scheduling and whole-placement acceptance remain open.
